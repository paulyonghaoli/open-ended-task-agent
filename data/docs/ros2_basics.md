# ROS2 Basics: Concepts and Two-Week Study Plan

## What is ROS2

ROS2 (Robot Operating System 2) is an open-source middleware framework for building robot software. Despite the name, it is not an operating system — it is a communication layer, build system, and tool ecosystem that sits on top of Linux, macOS, or Windows. ROS2 is the successor to ROS1, redesigned from the ground up to support real-time computing, multi-robot systems, security (DDS security), and production deployment.

ROS2 is the industry-standard framework used in research robotics, autonomous vehicles, industrial automation, and consumer robot products. Major users include NASA, Boston Dynamics, ABB, and virtually every academic robotics lab.

## Core Concepts

### Nodes

A node is the fundamental unit of computation in ROS2. Each node is an independent process (or a thread within a process) that performs a specific function: reading a sensor, running a control algorithm, publishing a pose estimate, or commanding a motor. Nodes communicate with each other through a standardized messaging API rather than direct function calls, which means nodes can be written in different languages, run on different machines, and be swapped out independently.

```python
import rclpy
from rclpy.node import Node

class MinimalPublisher(Node):
    def __init__(self):
        super().__init__("minimal_publisher")
        self.publisher_ = self.create_publisher(String, "topic", 10)
        self.timer = self.create_timer(0.5, self.timer_callback)

    def timer_callback(self):
        msg = String()
        msg.data = "Hello ROS2"
        self.publisher_.publish(msg)
```

### Topics and Messages

Topics are named communication channels. A publisher node sends messages to a topic; subscriber nodes receive them. Topics are asynchronous and one-to-many: one publisher, many subscribers. Messages are defined in `.msg` files and compiled into language-specific code. Common standard message types include `std_msgs/String`, `geometry_msgs/Twist` (velocity commands), `sensor_msgs/Image`, and `nav_msgs/Odometry`.

### Services

Services provide synchronous, request-response communication between two nodes. Unlike topics (fire-and-forget), a service call blocks until the server responds. Services are used for operations where you need an acknowledgment or a computed result: triggering a sensor calibration, querying robot status, or requesting a path plan.

### Actions

Actions extend services for long-running tasks that provide feedback during execution. An action has a goal (what to do), feedback (progress updates), and a result (final outcome). The Navigation2 stack uses actions for "navigate to pose" — the robot continuously publishes its distance to goal as feedback while moving.

### The DDS Middleware

ROS2 uses Data Distribution Service (DDS) as its underlying transport. DDS is an OMG standard for real-time, distributed publish-subscribe communication used in military, aerospace, and medical systems. ROS2 abstracts over multiple DDS implementations (Fast DDS, Cyclone DDS, Connext) via the RMW (ROS Middleware) interface. This gives ROS2 built-in QoS (Quality of Service) policies: reliability (best-effort vs reliable), durability (volatile vs transient-local), and deadline enforcement.

### Build System: colcon and ament

ROS2 packages are built with `colcon` (collective construction), which orchestrates builds across multiple packages in a workspace. Each package uses `ament_cmake` (for C++) or `ament_python` (for Python) as its build backend. The workspace directory structure is:

```
ros2_ws/
  src/
    my_package/
      package.xml
      setup.py
      my_package/
        __init__.py
        my_node.py
  install/  (generated by colcon build)
  build/    (generated by colcon build)
  log/      (generated by colcon build)
```

### Simulation: Gazebo

Gazebo is the standard simulator for ROS2. It provides physics simulation (rigid body dynamics, contact), sensor simulation (cameras, LIDAR, IMU, GPS), and a plugin system for custom actuators. ROS2-Gazebo integration is handled by the `gz_ros2_control` and `ros_gz_bridge` packages.

## Two-Week Study Plan

### Week 1: Fundamentals

**Day 1-2**: Installation and environment setup. Install ROS2 Humble (Ubuntu 22.04 recommended) or use the official Docker image. Source the setup script and verify with `ros2 doctor`. Run the talker/listener demo to confirm end-to-end communication.

**Day 3-4**: Core concepts. Read the official ROS2 tutorials on nodes, topics, and services. Write a Python publisher and subscriber from scratch. Use `ros2 topic echo` and `ros2 topic hz` to inspect live messages.

**Day 5-6**: Build system and packages. Create your own ROS2 Python package with `ros2 pkg create`. Write a custom message type. Build with `colcon build` and run your node.

**Day 7**: Services and parameters. Implement a service server and client. Use `ros2 param set` to configure a node at runtime. Explore `ros2 node info` and `ros2 service list`.

### Week 2: Applied Robotics

**Day 8-9**: TF2 (transform library). Understand the coordinate frame tree. Use `tf2_ros` to publish and listen to transforms. Visualize the frame tree in RViz2.

**Day 10-11**: Navigation2 basics. Launch a simulated TurtleBot3 in Gazebo. Run the Nav2 stack with a pre-built map. Send navigation goals via the RViz2 interface and the `NavigateToPose` action client.

**Day 12-13**: ROS2 Control. Understand the hardware abstraction layer. Write a simple joint trajectory controller. Connect it to a simulated robot in Gazebo.

**Day 14**: Integration project. Build a complete mini-project: a node that reads sensor data, runs a simple state machine, and commands the robot to navigate between two waypoints. Add logging and parameter-driven behavior.

## Recommendation

ROS2 Humble (LTS, supported until 2027) is the recommended starting distribution. Use Ubuntu 22.04 as the host OS for best compatibility. The Python client library (rclpy) is the most beginner-friendly entry point. Plan four to six weeks for comfortable productivity, not two — two weeks is enough to understand the architecture and complete basic examples, but production-quality robotics software takes longer to master.
